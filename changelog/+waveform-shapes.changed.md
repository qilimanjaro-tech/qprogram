`Gaussian`, `GaussianDragCorrection` and `IQDrag` take `num_sigmas` and `drag_coefficient` instead of `sigma` and `beta`, and their Gaussian changes shape: it is centred on `duration / 2` with standard deviation `duration / num_sigmas`, shifted down so the pulse starts at exactly 0, and rescaled back to its original peak, and the DRAG correction multiplies that same shifted curve and no longer scales with `resolution`. `FlatTop` becomes the sum of two error functions, each edge going from 0.2% to 99.8% of `amplitude` over `smooth_duration`, with `buffer` inside `duration` rather than padding around it, so `get_duration()` no longer adds `2 * buffer`. `SuddenNetZero` becomes `+amplitude` for half the pulse, one sample at `b * amplitude`, `t_phi` zeros, one sample at `-b * amplitude`, then `-amplitude`, so it is net zero for any `b`; `duration - t_phi` has to be even, and `t_phi` has to be an `int`, so it can no longer be swept. Each class documents the quirks its shape keeps, such as a negative `Gaussian` peaking below `amplitude` and a `FlatTop` whose edges do not fit coming out inverted.

The format version moves to 0.3, and no migration is registered, because no rewrite of the old parameters gives back the old pulses. A 0.2 file that uses `sigma` or `beta` now fails to load with `TypeError: Gaussian.__init__() got an unexpected keyword argument 'sigma'`, and its `FlatTop` and `SuddenNetZero` entries load with the new shapes, so those pulses have to be re-created rather than reloaded.
