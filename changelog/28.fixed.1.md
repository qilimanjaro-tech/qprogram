`dumps` no longer writes a fragment parameter in a `sync` bus list as its `repr`. `sync` was the one bus argument the format spells as a list, and it rendered each target through the writer's `serialize_bus`, which knows `BusRef` and quotes everything else; a parameter went out as the quoted string `"Parameter('drive')"`. The text still round-tripped byte-for-byte, but the reloaded fragment synchronized two buses of that literal name instead of the ones bound at the call site, and the program's bus set silently gained them. Targets now go through `serialize_value`, which is what every other operation's bus already used, so a parameter emits as the bare identifier the grammar's `value` rule has always accepted.
