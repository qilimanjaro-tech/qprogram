`register_profile` no longer rejects a rebuilt-but-identical `Profile`. The guard compared object identity, so an import-time side effect that ran twice, a reloaded module, or a re-executed notebook cell was told its own bundle was "already registered with different content" while the two profiles compared equal. Registration is now idempotent for an equal profile and raises only when the content actually differs. Of an equal pair the registry keeps the first object, so the profile just passed in is not necessarily the one `resolve_profile` returns.
